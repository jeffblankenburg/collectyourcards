# Production migration — Azure SQL Server → Supabase Postgres

Metadata-driven, full-database migration (issues **#16 / #17 / #18**). It introspects the
**live** SQL Server catalog and drives DDL generation, ETL, and verification from that single
source of truth — so it reflects the real database exactly (which has drifted well beyond the
old `prisma/schema.prisma`: 92 tables, ~2.1M rows).

## Commands
```bash
cd migration
npm install
npm run inspect   # print table inventory, row counts, FK graph, load order, type coverage
npm run migrate   # drop+recreate target schema, stream-COPY all data, add FKs, reset identities
npm run verify    # count parity + FK integrity + sampled field diff + collection reconciliation
npm run all       # migrate + verify
```
Reads `LEGACY_SQL_SERVER_*` and `SUPABASE_DIRECT_CONNECTION_STRING` from the repo-root `.env`.
Data lands in the **`legacy`** schema (configurable via `TARGET_SCHEMA`).

## How it works
- **`catalog.ts`** — introspects columns (incl. identity/computed), PKs, FKs, row counts; topo-sorts
  tables parents-first and detects FK cycles.
- **`ddl.ts`** — SQL Server→Postgres type map (covers all 11 types in use); identity columns become
  `GENERATED BY DEFAULT AS IDENTITY` (preserves original IDs, auto-generates afterward); computed
  columns are materialized as plain columns so derived data is preserved.
- **`migrate.ts`** — streams each table from SQL Server and `COPY`s into Postgres with backpressure;
  FK constraints are added **after** load (dodges cycle/order issues, far faster than per-row checks);
  identity sequences reset to `MAX(id)+1`. **Idempotent** — safe to re-run (drops+rebuilds the schema).
- **`verify.ts`** — exact row-count parity (all tables), FK-orphan = 0 (all relationships), sampled
  field-for-field diff vs source on the largest tables, and `user_card` money-total reconciliation.

## Proven results (real run)
- **2,108,594 rows / 92 tables migrated in ~60s** (~35k rows/s via streaming COPY).
- **145 FK constraints added, 0 failures**; 90 identity sequences reset.
- **Verify PASSED:** 92/92 count parity, 145/145 FK relationships orphan-free, 1,200 sampled rows
  match field-for-field, collection reconciled ($6,546.41 purchase / $7,689.47 estimated).

## Notes
- Schema trim (#16) defaults to **migrate everything** (data-preservation first). Defer/drop
  candidates are listed, commented, in `src/config.ts → SKIP_TABLES`.
- The Postgres **Prisma schema** is generated by introspection into `prisma/schema.prisma`
  (`npx prisma db pull`) — 92 valid models.
- Search redesign (replacing legacy `*_indexed` columns with `pg_trgm`/`tsvector`): see `SEARCH.md`.
- Connection: the direct `db.<ref>.supabase.co` host is IPv6-only/unresolvable here; use the
  **session pooler** (`aws-1-us-east-2.pooler.supabase.com:5432`).
